# 求人広告 運用ダッシュボード(スタンドアロン版)

エアワークの「求人ごとの配信実績」CSVを拠点別に取り込み、成績の悪い求人から優先順位をつけ、
修正日からの効果測定を行うためのダッシュボードです。ビルド不要、`index.html` を1つ開くだけで動きます。

## 1. GitHubへのアップロード方法

1. GitHubで新しいリポジトリを作成します(例: `job-ad-dashboard`)
2. このフォルダの中身(`index.html` と `README.md`)をリポジトリにアップロードします
   - GitHubの画面右上の「Add file」→「Upload files」から、この2ファイルをドラッグ&ドロップしてください
   - コミットメッセージは何でも構いません(例: `初回アップロード`)→「Commit changes」

## 2. GitHub Pagesを有効にする(ブラウザから直接開けるようにする)

1. リポジトリの「Settings」→左メニューの「Pages」を開く
2. 「Build and deployment」の「Source」を **Deploy from a branch** に設定
3. 「Branch」を `main`(または `master`)、フォルダを `/ (root)` にして **Save**
4. 数十秒〜数分待つと、ページ上部に公開URLが表示されます
   (例: `https://ユーザー名.github.io/job-ad-dashboard/`)
5. そのURLを開けば、どのPC・ブラウザからでもダッシュボードにアクセスできます

## 3. データの保存について(重要)

このスタンドアロン版は、Claude上で動いていたアーティファクト版と違い、
**データをブラウザの localStorage に保存**します。つまり:

- **同じブラウザ・同じ端末で開く限り**、取り込んだ求人データは残り続けます
- **別の端末やブラウザで開くと、データは空の状態**になります(localStorageは端末ごとに独立しているため)
- ブラウザのキャッシュ・閲覧履歴を消去すると、データも一緒に消えます

複数人・複数端末で使う場合や、データ消失のリスクに備えるために、
ヘッダー右上の **「バックアップ保存」** ボタンでJSONファイルとしてデータを書き出せます。
別端末で使う場合は、同じくヘッダーの **「バックアップ復元」** からそのJSONを読み込めば、
取り込み済みのデータを引き継げます。

> 運用のおすすめ: 毎回のCSV取り込み後に「バックアップ保存」を行い、
> 会社の共有ドライブなどにJSONファイルを置いておくと、端末が変わっても安心です。

## 4. 使い方

1. 拠点(plus-i / plus-c / next / up)ごとのボタンから、
   AirWorkの「求人ごとの配信実績」CSV(求人番号・求人内容・求人メモを含む形式)を取り込みます
2. 企業名は求人メモから自動抽出されます(間違っていれば詳細画面から手動修正可能。一度直すと以降は上書きされません)
3. 前回取り込み時と「求人内容」(タイトル)が変わっていた場合、自動的に「修正日」として記録されます
   - タイトルが変わらない修正(画像差し替えなど)は、詳細画面の「修正日として記録」ボタンで手動追加できます
4. 一覧は「応募数が少ない順→クリック率が低い順」で並び、上位3件が赤くハイライトされます
5. タブで「全体」「拠点ごと」を切り替えられます
6. 求人をクリックすると詳細画面が開き、推移グラフ・修正前後の効果比較(クリック数/日の変化率)を確認できます
7. 毎月10日・20日・30日にはヘッダーに更新リマインドが表示されます

## 5. 技術メモ

- React・Recharts・PapaParseはすべてCDN(unpkg)から読み込みます。**インターネット接続が必要**です
- ビルド不要(`<script type="text/babel">` でブラウザ上でJSXを変換しています)
- 何らかの理由でCDNの読み込みが失敗する場合は、社内ネットワークでunpkg.comへのアクセスが
  制限されていないかご確認ください
