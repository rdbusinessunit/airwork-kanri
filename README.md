# 求人広告 運用ダッシュボード(GitHub Pages + Supabase版)

エアワークの「求人ごとの配信実績」CSVを拠点別に取り込み、成績の悪い求人から優先順位をつけ、
修正日からの効果測定を行うためのダッシュボードです。データはSupabase(無料のクラウドDB)に保存されるため、
**どの拠点のPC・ブラウザから開いても同じデータを共有**できます。

## 0. 事前準備:Supabaseにテーブルを作る(初回のみ)

1. Supabaseのダッシュボードにログイン
2. 左メニューの「SQL Editor」を開く
3. 同梱の `setup.sql` の中身をすべて貼り付けて実行(RUN)
4. `jobs` というテーブルができていればOK

`index.html` にはすでにSupabaseの接続情報(Project URLとpublishable key)が埋め込まれています。
これらは公開されても問題ない種類のキーです(書き込み制限はテーブル側のポリシーで管理しています)。

## 1. GitHubへのアップロード方法

1. GitHubで新しいリポジトリを作成します(例: `job-ad-dashboard`)
2. `index.html` をリポジトリにアップロードします(「Add file」→「Upload files」)

## 2. GitHub Pagesを有効にする

1. リポジトリの「Settings」→「Pages」
2. 「Source」を **Deploy from a branch** に設定
3. 「Branch」を `main`、フォルダを `/ (root)` にして **Save**
4. 発行されたURL(例: `https://ユーザー名.github.io/job-ad-dashboard/`)を各拠点の担当者に共有

## 3. 検索エンジン対策(任意)

このページが検索結果に出てほしくない場合は、同じリポジトリに以下の内容で
`robots.txt` というファイルを追加してください。

```
User-agent: *
Disallow: /
```

あわせて、リンクをどこにも公開リンクとして貼らない(社内チャット等の非公開経路だけで共有する)ことで、
実質的に外部から見つかることはほぼなくなります。完全なアクセス制限が必要な場合は、
別途ログイン機能の追加をご相談ください。

## 4. 使い方

1. 拠点(plus-i / plus-c / next / up)ごとのボタンから、
   AirWorkの「求人ごとの配信実績」CSV(求人番号・求人内容・求人メモを含む形式)を取り込みます
2. 企業名は求人メモから自動抽出されます(間違っていれば詳細画面から手動修正可能)
3. 前回取り込み時と「求人内容」(タイトル)が変わっていた場合、自動的に「修正日」として記録されます
4. 一覧は「応募数が少ない順→クリック率が低い順」で並び、上位3件が赤くハイライトされます
5. タブで「全体」「拠点ごと」を切り替えられます
6. ヘッダーの「バックアップ保存」で、念のためのJSONバックアップもいつでも取れます

## 5. 技術メモ

- React・Recharts・PapaParseはCDN(unpkg)から読み込みます。**インターネット接続が必要**です
- データの保存・読み込みはSupabaseのREST API(PostgREST)を直接呼び出しています
- テーブルの行レベルセキュリティ(RLS)は「公開キーからの全操作を許可」に設定しています。
  URLとキーを知っている人は誰でもデータを読み書きできる、社内共有ツールとしての想定です
