# 求人広告 運用ダッシュボード(GitHub Pages + Supabase版)

エアワーク・求人BOXの配信実績CSVを媒体別・拠点別に取り込み、成績の悪い求人から優先順位をつけ、
修正日からの効果測定を行うためのダッシュボードです。データはSupabase(無料のクラウドDB)に保存されるため、
**どの拠点のPC・ブラウザから開いても同じデータを共有**できます。

## 0. 事前準備:Supabaseにテーブルを作る(初回のみ)

1. Supabaseのダッシュボードにログイン
2. 左メニューの「SQL Editor」を開く
3. 同梱の `setup.sql` の中身をすべて貼り付けて実行(RUN)
4. `jobs` というテーブルができていればOK

`index.html` にはすでにSupabaseの接続情報(Project URLとpublishable key)が埋め込まれています。
これらは公開されても問題ない種類のキーです(書き込み制限はテーブル側のポリシーで管理しています)。

## 1. GitHubへのアップロード方法

1. GitHubで新しいリポジトリを作成します(例: `job-ad-dashboard`)
2. `index.html` と `vendor` フォルダ(中に6つの.jsファイルが入っています)を、
   **フォルダ構造を保ったまま**リポジトリにアップロードします
   - 「Add file」→「Upload files」で、`index.html`と`vendor`フォルダごとドラッグ&ドロップすると、
     フォルダ構造を保ったままアップロードできます
   - `vendor`フォルダの中身が`index.html`と同じ階層の`vendor/`に入っている状態が正解です

## 2. GitHub Pagesを有効にする

1. リポジトリの「Settings」→「Pages」
2. 「Source」を **Deploy from a branch** に設定
3. 「Branch」を `main`、フォルダを `/ (root)` にして **Save**
4. 発行されたURL(例: `https://ユーザー名.github.io/job-ad-dashboard/`)を各拠点の担当者に共有

## 3. 検索エンジン対策(任意)

このページが検索結果に出てほしくない場合は、同じリポジトリに以下の内容で
`robots.txt` というファイルを追加してください。

```
User-agent: *
Disallow: /
```

あわせて、リンクをどこにも公開リンクとして貼らない(社内チャット等の非公開経路だけで共有する)ことで、
実質的に外部から見つかることはほぼなくなります。完全なアクセス制限が必要な場合は、
別途ログイン機能の追加をご相談ください。

## 4. 使い方

まず画面上部の媒体タブ(**エアワーク / 求人BOX**)を選び、その下の拠点ボタンからCSVを取り込みます。
媒体ごとにデータは完全に分かれているため、一覧・タブ・検索はすべて選択中の媒体だけが対象になります。

### エアワーク

1. 拠点(plus-i / plus-c / next / up)ごとのボタンから、
   AirWorkの「求人ごとの配信実績」CSV(求人番号・求人内容・求人メモを含む形式)を取り込みます
2. 企業名は求人メモから自動抽出されます(間違っていれば詳細画面から手動修正可能)
3. 前回取り込み時と「求人内容」(タイトル)が変わっていた場合、自動的に「修正日」として記録されます

### 求人BOX

1. 拠点(plus / next / up)ごとのボタンから、求人BOX管理画面の「求人別」レポートCSVを取り込みます
2. 求人BOXのCSVは **plus / next / up が1ファイルにまとまって出力される** ため、
   「勤務先名」から拠点を自動で振り分けます(判定できない行だけ、押したボタンの拠点に入ります)。
   どのボタンから取り込んでも結果は同じです
3. ステータスが「**募集停止**」の求人は取り込みません(一覧が終了案件で埋まるのを防ぐため)
4. 求人BOXのCSVに顧客企業名は含まれないため、**企業名は詳細画面から手入力**します。
   一覧の企業名欄の下には勤務地・勤務先名・キャンペーン名が表示されます
5. 前回取り込み時と「求人タイトル」が変わっていた場合、自動的に「修正日」として記録されます

### 共通

1. 一覧は「応募数が少ない順→クリック率が低い順」で並び、上位3件が赤くハイライトされます
2. タブで「全体」「拠点ごと」を切り替えられます
3. ヘッダーの「バックアップ保存」で、念のためのJSONバックアップもいつでも取れます

### 数値の読み方の違い(重要)

- エアワークの数値は**掲載開始からの累計**です
- 求人BOXの数値は**ファイル名の期間(例: `_20260901_20260908`)の合計**です。
  月をまたぐと集計がリセットされるため、ダッシュボードは期間の起点が変わったことを検知して、
  前回との単純な引き算にならないように増分を計算します
- 求人BOXのCSVには「応募開始数」「応募完了率」にあたる指標がありません(その分の欄は空になります)

## 5. 技術メモ

- React・Recharts・PapaParseなど必要なライブラリは、すべて`vendor`フォルダにファイルとして同梱しています。
  外部CDN(unpkgなど)には一切アクセスしないため、**社内ネットワークの通信制限があっても問題なく動作**します
- データの保存・読み込みだけはSupabaseのREST API(PostgREST)を直接呼び出すため、
  Supabaseの通信(`*.supabase.co`)は許可されている必要があります
- **Supabaseのテーブル定義(`setup.sql`)の変更は不要です。** 媒体は`job_id`の接頭辞で区別しており、
  求人BOXの求人は `kb:7874-6942-0001` のように保存されます(画面上は接頭辞なしで表示)。
  既存のエアワークのデータはそのまま使えます
- エアワークのCSVはUTF-8、求人BOXのCSVはShift_JISで出力されるため、
  ファイルのバイト列から文字コードを判定して読み込みます
- 求人BOXのCSVは数千行になるため、Supabaseへの保存は500件ずつまとめて送ります
